# Project 2 — Real-Time Streaming & Dashboards

Part of the **Matrix Data Mühəndisliyi** final project series. A real-time
streaming analytics pipeline built on Kafka, Spark Structured Streaming,
PostgreSQL, Airflow, and Metabase — using live ADS-B air traffic data from
the [OpenSky Network](https://opensky-network.org) as the source.

## Architecture

```
OpenSky API  --(OAuth2)-->  Producer (Python)  -->  Kafka (aircraft_state_v1)
                                                          |
                                                          v
                                          Spark Structured Streaming
                                          (watermarked windows)
                                                /              \
                                               v                v
                                    aircraft_state          flight_window_metrics
                                       (Postgres)                (Postgres)
                                                \              /
                                                 v            v
                                                   Metabase dashboards

Airflow schedules the producer to run every 2 minutes.
```

## Tech Stack

| Component | Role |
|---|---|
| Apache Kafka (Confluent images) | Event backbone — topic `aircraft_state_v1` |
| Python producer | Polls OpenSky `/states/all`, publishes to Kafka |
| Spark Structured Streaming (pyspark, custom Docker image) | Consumes Kafka, computes windowed metrics, writes to Postgres |
| PostgreSQL | Serving store — curated events + windowed aggregates |
| Apache Airflow (standalone) | Schedules the producer |
| Metabase | Dashboards on top of PostgreSQL |

## Setup & Run

1. **Get OpenSky credentials** — create a free account at
   [opensky-network.org](https://opensky-network.org), generate an API
   client under Account settings, download the `credentials.json`
   (`{"clientId": ..., "clientSecret": ...}`) and place it at
   `producer/credentials.json`. Without it the producer still works, just
   heavily rate-limited (anonymous access).

2. **Start everything:**
   ```bash
   docker-compose up -d --build
   ```
   First run downloads several images/JARs (Kafka, Postgres, Spark's Kafka
   connector, JDBC driver) — can take a few minutes.

3. **Get the Airflow admin password** (auto-generated by `standalone` mode,
   *not* the `admin`/`admin` env vars):
   ```bash
   docker exec -it airflow cat /opt/airflow/standalone_admin_password.txt
   ```
   Log in at `http://localhost:8081` with username `admin` and that password,
   find the `opensky_producer` DAG, and toggle it on.

4. **Connect Metabase** at `http://localhost:3000` — PostgreSQL, host
   `postgres`, port `5432`, database `streaming`, user/password `matrix`.

5. **Dashboard queries** (SQL question type in Metabase):

   *Flight density over time* (Line chart):
   ```sql
   SELECT window_start, active_flights
   FROM flight_window_metrics
   ORDER BY window_start;
   ```

   *Top callsigns* (Bar chart):
   ```sql
   SELECT trim(callsign) AS callsign, count(*) AS records
   FROM aircraft_state
   WHERE callsign IS NOT NULL AND trim(callsign) <> ''
   GROUP BY trim(callsign)
   ORDER BY records DESC
   LIMIT 10;
   ```

   *Live aircraft map* (Pin map):
   ```sql
   SELECT DISTINCT ON (icao24) icao24, latitude, longitude, callsign, event_time
   FROM aircraft_state
   WHERE latitude IS NOT NULL AND longitude IS NOT NULL
   ORDER BY icao24, event_time DESC;
   ```

## Data Model

**`aircraft_state`** — one row per state vector ingested (curated feed).
Primary key `(icao24, event_time)`.

**`flight_window_metrics`** — 1-minute windowed aggregates: `active_flights`,
`avg_altitude`, `vertical_rate_anomalies` (|vertical_rate| > 15 m/s).
Primary key `(window_start, window_end)`.

## Design Notes & Known Limitations

- **No standalone Spark cluster.** `bitnami/spark` images were paywalled by
  Broadcom's 2025 catalog restructuring, so Spark runs via `pip install
  pyspark` inside a custom-built container (Debian **bookworm**, not the
  default `slim` tag, since the newer Debian release dropped `openjdk-17`
  from apt — Spark 3.5.x doesn't officially support Java 21).
- **`approx_count_distinct`, not `countDistinct`** — Structured Streaming
  doesn't support exact distinct aggregations on streaming DataFrames.
- **Windowed output uses `append` mode** — emits each window once, after
  the 2-minute watermark passes it, avoiding primary-key conflicts on the
  JDBC sink (which has no native upsert support in Structured Streaming).
- **Airflow `standalone` + SQLite** is a dev/teaching setup, not
  production — no persistent metadata volume, single container for
  webserver+scheduler+triggerer.
- **OpenSky credit budget**: ~4000 requests/day authenticated. Polling
  every 2 minutes (720 requests/day) stays comfortably inside that.
